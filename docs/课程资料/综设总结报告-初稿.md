## 摘 要

本项目面向数字电路课程的教学与实验场景，开发了一套数字电路原理图编辑与组合逻辑仿真软件 MyEDA。软件以 C++17 为核心语言，基于 wxWidgets 构建跨平台图形界面，使用 CMake 组织构建，实现了"搭建数字电路 → 连线与编辑 → 组合逻辑仿真 → 工程保存 → 导出标准 PCB 交换文件"的完整流程。项目重点解决了三个复杂工程问题：一是原理图图形结构与电气网表之间的一致性保持，二是撤销/重做等编辑状态在多模块间的一致管理，三是与工业标准 EDA 工具（KiCad、gEDA）的文件格式互操作。针对上述问题，团队采用公共数据模型与模块化分层架构，通过命令化编辑、双缓冲渲染、结构化 JSON 校验和严格的格式逆向对齐等方案加以解决，并以 227 项自动化测试与真实 EDA 工具实测形成验证闭环。最终软件完成了逻辑门/开关/指示灯的原理图搭建、组合逻辑实时仿真、半加器与全加器等典型电路的端到端验收，并成功将原理图导出为 gEDA 网表与初始布局，在 pcb-rnd 中实现了全部网络自动布线与 Gerber 导出，达成了课程任务的全部定标要求。

**关键词**：数字电路；原理图编辑；组合逻辑仿真；EDA 互操作；C++；自动化测试

## 第一章 复杂工程问题归纳与实施方案可行性研究

### 1.1 需求分析与建模

（*此节由全体成员结合各自模块补充具体建模图，如用例图、状态图、数据流图；以下为文字要点。*）

本项目源于数字电路课程实验中对"画得出、连得对、仿得准、交得出"的实际需求。传统实验教学依赖实物面包板或国外商业 EDA 软件，前者元件有限、接线易错，后者门槛高、与课程内容脱节。因此课题确立的目标是：开发一款轻量、可离线运行、贴合数字电路教学的原理图编辑与逻辑仿真一体化软件，并能与工业标准 EDA 工具链对接，使学生在课程内完成的电路能进一步进入 PCB 制作流程。

通过分析课程应用场景，软件需求归纳为五个方面：

1. **原理图编辑需求**：提供常用数字元件（与/或/非/异或/与非/或非门、开关、指示灯、时钟源、D 触发器、自定义元件），支持元件放置、直角折线连线、选择、移动、复制粘贴、删除、撤销重做、缩放平移等编辑操作。
2. **逻辑仿真需求**：对组合逻辑电路进行实时传播计算，点选开关即时重算全部节点电位，按电平对导线着色，直观呈现信号流向。
3. **工程持久化需求**：支持工程保存与重新打开，保证编辑现场完整恢复；对文件进行结构化校验，拒绝损坏或非法数据。
4. **互操作需求**：能导出 KiCad 原理图与网表；能导出 gEDA 网表与初始 PCB 布局，接入开源 EDA 工具链进入布线制板环节。
5. **可验证需求**：软件逻辑必须可自动化回归，避免教学演示中出现不可复现的错误。

在需求建模上，团队采用软件工程方法对系统进行结构化描述：以**用例图**刻画"搭建电路、编辑连线、运行仿真、保存工程、导出交换文件"五类核心用例与参与者（学生用户）的关系；以**状态图**描述编辑文档在"干净/未保存/仿真中/只读"等状态间的迁移，用于约束仿真过程中的编辑行为；以**数据流图**刻画元件库定义、画布元件、连线拐点、连接网表、仿真结果之间的数据转换关系。这些模型为后续模块划分和接口定义提供了统一依据。

### 1.2 复杂工程问题归纳

在需求分析基础上，团队归纳出三个必须解决、且具有工程复杂度的问题：

**问题一：图形结构与电气网表的一致性保持。** 原理图本质是图形（元件符号、连线拐点、位置），而仿真和导出依赖的是电气连接关系（网络、引脚、扇出）。用户的一次拖动、增删连线或自定义元件修改，会同时影响图形与电气两个视图。若两者缺乏统一数据源，极易出现"画面对但仿错"或"导出网表与图不符"的隐性错误。如何以单一权威数据模型同时驱动渲染、仿真与导出，是首要复杂问题。

**问题二：编辑状态在多模块间的一致管理。** 撤销/重做、未保存标记、只读约束、自定义元件库变更，横跨界面层（A）、画布层（B）、文件层（C）与仿真层（D）。任何一处状态不同步，都会导致"撤销后元件库与画布不一致""仿真中仍可编辑导致数据竞争""关闭时未提示保存"等缺陷。如何在四个模块间维持一致的文档状态机，是第二个复杂问题。

**问题三：与工业 EDA 工具的文件格式互操作。** KiCad 与 gEDA 是两套格式迥异、且无官方文档完整覆盖内部细节的工业格式。要实现导出，必须逆向对齐其文本格式、坐标量级、封装模板与网表语义，并保证导出文件能被真实工具接受并进入布线流程。这既涉及格式细节的准确性，也涉及跨工具链的验证方法，是第三个复杂问题。

### 1.3 实施方案与可行性研究

（*此节可由 C/B 补充概要设计与详细设计的类图、模块图。*）

针对上述问题，团队确立"公共数据模型 + 模块化分层"的总体方案：以一个权威的电路数据模型（元件列表、连线、元件库定义）作为单一数据源，界面、画布、文件、仿真四个模块均通过该模型读写，从架构上保证图形与电气的一致性（解决问题一）；将文档状态（脏标记、撤销栈、只读标志）集中管理，所有编辑以命令化方式作用于模型并同步状态（解决问题二）；文件模块对 KiCad、gEDA 两种格式分别实现独立的导出器，并严格按真实工具的样例文件逆向对齐格式细节（解决问题三）。

技术选型上采用 **C++17 + wxWidgets + CMake**：C++17 提供足够的抽象能力与运行效率；wxWidgets 是成熟的跨平台原生 GUI 库，适合教学软件的界面需求且无授权负担；CMake 支持跨平台构建与自动化测试集成。可行性从三方面论证：一是团队已完成 C++ 与数字电路先修课程，具备实现基础；二是 wxWidgets 与 CMake 均为开源成熟生态，环境搭建成本低；三是组合逻辑仿真为纯软件计算，无需硬件依赖，可在本地完整闭环验证。在方案落地过程中，团队还对主要技术风险做了预判并准备应对措施：一是**跨模块一致性风险**，即界面、画布、文件、仿真对同一份数据的并发读写可能引发状态错乱，应对措施是统一数据访问入口、把文档状态集中管理，并以自动化测试覆盖状态迁移；二是**格式互操作风险**，即 KiCad/gEDA 内部格式缺乏完整官方文档、版本演进可能导致格式细节变化，应对措施是以真实工具的样例文件逐字段逆向对齐，并坚持"导出后必须被真实工具加载验证"的闭环，而不是仅凭自身解析通过；三是**进度风险**，即四个模块并行开发可能在集成阶段集中暴露接口不匹配问题，应对措施是先冻结公共接口再分头开发，并通过持续集成的自动化测试尽早发现集成问题。综合技术、资源、进度三方面评估，方案切实可行。

## 第二章 存在问题与解决方案

### 2.1 存在的主要问题

项目推进过程中，通过自动化测试、真实工具实测与人工操作复核，陆续暴露出若干真实工程问题，归纳为四类：

**问题一：编辑状态跨模块泄漏。** 自动化测试发现，新建工程后文档的"只读"标志未被复位，导致新画布上放置时钟源等元件失败、仿真采样出现空记录，进而引发波形窗口崩溃。根因是文档状态（只读标志）在切换/新建工程时未随数据一并复位，属跨模块状态管理缺陷。

**问题二：仿真波形窗口无法正常显示与刷新。** 波形窗口最初打开后空白，且手动制造开关跳变后不能正确反映电平变化。排查发现三个叠加缺陷：绘制事件未绑定导致窗口不重绘、存在遮挡面板、跳变沿的绘制逻辑分段错误。

**问题三：对第三方工具缺陷的误判。** 在验证 gEDA 导出链路时，自动布线一度报 "rats nest is stale" 中止。团队起初将其归因为 pcb-rnd 对传统 gEDA 元件的兼容缺陷，并以"老师参考文件同样失败"作为佐证。这一误判差点让团队放弃自动布线、退回纯人工演示。

**问题四：KiCad 走线网络归属错误。** 初版脚本布线将所有走线写入同一网络号，且走线几何穿过无关焊盘，虽视觉上"连上了"，但未通过设计规则检查（DRC），不能算真正完成布线。

### 2.2 解决方案

**针对问题一**，将文档状态集中到统一的文档对象中管理，新建/切换工程时随电路数据一并复位只读标志与脏标记；同时在仿真运行期间对编辑操作加约束。修复后回归测试覆盖"新建工程可正常放置元件与仿真"场景。

**针对问题二**，将波形窗口的绘制显式绑定到重绘事件、移除遮挡面板、重写方波绘制逻辑（水平段延伸至步进边界、在电平变化处补竖直跳变沿），并补充 9 项针对波形渲染的自动化测试。最终通过真实点击开关制造跳变、逐像素核对三条轨迹的跳变沿位置完成验证。

**针对问题三**，团队重新系统性排查工具链，定位到真实根因是**我方脚本漏了 `AddRats(AllRats, manhattan)` 这一步**——在调用自动布线前必须先生成飞线。补上该步骤后，我方导出文件与老师参考文件均能正常布通。这一过程也带来方法论启示：在宣告"工具无解"之前，必须逐层实测、不能以未做对照的巧合现象下结论。

**针对问题四**，重写布线脚本，改为从板子读取真实焊盘位置与真实网络号，采用网格迷宫（Lee）算法把同一网络的焊盘连成树、并自动绕开其他焊盘与其他走线，最后补齐板框。重做后走线按 4 个网络正确分布，`kicad-cli pcb drc` 检查结果为 0 错误、0 未连通项。

上述问题的发现与解决，均依赖 227 项自动化测试与真实工具实测形成的验证闭环，而非仅凭界面观察判断。

## 第三章 执行情况与完成度

本项目按"功能收尾 → 验证闭环 → 文档同步"推进，各子任务完成情况如下：

| 子任务 | 内容 | 完成度 | 验证方式 |
|---|---|---|---|
| 原理图编辑 | 元件放置、直角连线、选择编辑、撤销重做、缩放平移 | 完成 | 画布交互自动化测试 |
| 组合逻辑仿真 | 实时传播计算、导线电位着色、半加器真值表验收 | 完成 | 仿真单元测试 |
| 工程保存与校验 | 结构化 JSON 存档、重开恢复、非法数据校验 | 完成 | 存档往返测试 |
| KiCad 互操作 | 导出原理图与网表，KiCad 加载 0 错误 | 完成 | KiCad 10 实测 |
| gEDA 互操作（任务5定标） | 导出网表与初始布局，pcb-rnd 加载并自动布线 | 完成 | pcb-rnd 8/8 网络布通、0 短路、13 个 Gerber |
| 时序波形展示 | 波形窗口绘制与时序跳变呈现 | 完成 | 9 项渲染测试 + 真实点击逐像素核对 |
| 自动化测试 | 三套测试套件 | 227 项全通过 | test_sim 89 + test_modules 53 + test_canvas 85 |

在执行过程管理上，团队坚持两条质量纪律。其一，**每次提交须通过全部自动化测试**，新增功能必须附带对应测试用例，避免"功能加上去了但没人守得住"；三套测试分别覆盖仿真逻辑、模块单元与画布交互渲染，形成从算法到界面的分层回归能力。其二，**新功能必须同步更新使用指南与截图，并保持文档一致性检查通过**，使软件能力、用户文档与答辩口径三者始终对齐，避免临近期末才发现文档与实现脱节。

验证方法上，团队特别强调"真实工具实测"优先于"自身解析通过"。以互操作为例，导出文件不仅要能被自己的解析器读回，更必须能被 KiCad、pcb-rnd 等真实工具正常加载、布线并导出生产文件；为此团队专门搭建了基于 WSL 的真实工具验证环境，对每条导出链路做端到端实测并留存原始日志，确保结论可靠、可复现。

截至结题，课程任务定标的全部要求均已完成并通过实机验证：软件能完整走通"画原理图 → 连线编辑 → 组合逻辑仿真 → 工程保存 → 导出 KiCad/gEDA 文件 → 真实 pcb 工具自动布线 → 导出 Gerber"的端到端流程。需要说明的是，"Gerber 已导出"不等于"已送厂制板验证"，答辩口径据此把握。

## 第四章 分工协作与交流情况

项目采用按功能模块划分责任的协作方式，四名成员各负责一个核心模块，并通过公共数据模型与联合验收完成集成：

- **郑晨曦（B，2025091601016）——绘图画布与编辑**：负责画布渲染、网格吸附、直角折线、选择与编辑、撤销重做、缩放平移与渲染性能优化。

- **杨谨淳（D，2025091601003）——仿真、测试与集成**：负责组合逻辑计算、自动化测试体系、构建脚本与演示版本验证。

协作机制上，团队以公共接口（如选择回调、元件库增删改接口、连接数据校验入口）约定模块边界，跨模块功能由相关成员共同设计接口后再分头实现；每次集成通过统一的自动化测试套件做联合验收，避免"各模块自测通过、集成后出错"。交流方面，团队定期同步进度与阻塞点，对跨模块缺陷（如第一章所述的状态管理、渲染一致性问题）组织联合排查，并将结论写入共享文档，保证知识在组内沉淀。
